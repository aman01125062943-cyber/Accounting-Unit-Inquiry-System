# نموذج البيانات - نظام الاضابير (014-archives-system)

## الجداول الجديدة

### 1. جدول `ArchiveBatches` (ملخصات الأرشفة)
يخزن السجلات المجمعة التي تظهر في شاشة الاضابير الرئيسية.

| الحقل | النوع | الوصف |
| :--- | :--- | :--- |
| `Id` | INTEGER | مفتاح أساسي تلقائي |
| `ExcelNames` | TEXT | أسماء ملفات الإكسيل المتأثرة (مفصولة بفاصلة) |
| `RecordCount` | INTEGER | عدد السجلات المؤرشفة في هذه العملية |
| `DateFrom` | TEXT | بداية الفترة الزمنية المختارة |
| `DateTo` | TEXT | نهاية الفترة الزمنية المختارة |
| `SourceTable` | TEXT | الجدول الأصلي (Returns / SalaryReturns) |
| `Reason` | TEXT | سبب الأرشفة (إلزامي، 5 أحرف فأكثر) |
| `ArchivedAt` | TEXT | تاريخ ووقت العملية (ISO-8601) |

### 2. جدول `ArchiveDetails` (السجلات التفصيلية)
يخزن البيانات الكاملة لكل سجل تمت أرشفته.

| الحقل | النوع | الوصف |
| :--- | :--- | :--- |
| `Id` | INTEGER | مفتاح أساسي تلقائي |
| `BatchId` | INTEGER | معرف الدفعة (FK -> ArchiveBatches.Id) |
| `OriginalId` | INTEGER | المعرف الأصلي في جدول المصدر |
| `RawData` | TEXT | السجل الكامل بصيغة JSON |

## العلاقات (Relationships)
- **علاقة (1:N)**: كل سجل في `ArchiveBatches` مرتبط بعدة سجلات في `ArchiveDetails`.
- عند حذف (أو استعادة) الـ Batch، يتم التعامل مع كافة التفاصيل المرتبطة به.

## قواعد التحقق (Validation Rules)
1. **السبب (`Reason`)**: يجب ألا يقل عن 10 أحرف.
2. **الاستعادة**: عند الاستعادة، يتم التأكد من عدم وجود تضارب في المعرفات الأصلية في الجدول المستهدف.
3. **الفترة الزمنية**: يجب أن يكون `DateTo` لاحقاً لـ `DateFrom`.
